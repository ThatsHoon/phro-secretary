# 시행착오 기록

유지보수 중 같은 문제를 다시 겪지 않도록, 실제로 겪은 증상·원인·해결을 모은다. 새 항목은 해당 절에 추가한다.
형식: **증상** → 원인 → 해결(위치).

## 1. 그래프 저장소 · 임베딩

- **설치 파일만으로는 기억 검색이 동작하지 않았다.** → 그래프 DB(FalkorDB)가 Windows 빌드가 없어 WSL Ubuntu 안에서 돌았다.
  WSL 설치·systemd 서비스·세션 유지(WSL은 Windows 쪽 프로세스가 없으면 distro를 수 초 안에 내린다)·localhost 포워딩 장애
  구분까지 앱이 떠안았다. → 그래프를 원본 DB 옆 SQLite 파일(`memory.graph.db`)로 옮겼다(`memory/graph.py`).
  FalkorDB의 벡터 검색도 인덱스 없이 전체를 비교했으므로 numpy 전체 비교와 같은 방식이고, 전문검색은 FTS5 bm25로 대체했다.
  1만 기억 기준 수치는 [architecture.md](architecture.md) "검증". WSL·Redis·FalkorDB 의존성이 모두 빠졌다.
- **SQLite로 옮긴 뒤에도 임베딩 때문에 Ollama를 따로 설치해야 했다.** → 같은 모델(nomic-embed-text v1.5)을 ONNX로
  프로세스 안에서 돌린다(`memory/embedder.py`). 내보내기 비교: fp16은 fp32와 코사인 1.0, int8은 0.95~0.96이라 fp16을 쓴다.
  Ollama와는 영어 문장이 1.0인데 한국어는 0.78~0.86이다. 풀링·정규화가 같으니 원인은 토크나이저로 본다:
  HF 공식 토크나이저(학습 기준, uncased라 한글을 자모로 분해)와 Ollama 쪽이 다르게 자른다. 공식 토크나이저를 따른다.
  그래프는 설정 변경으로 한 번 다시 만들어진다.
- **`tokenizers`가 huggingface_hub과 그 네트워크 의존성(httpx, hf-xet 등)을 끌고 왔다.** → 모델 다운로드에만 쓰이고 앱은
  파일에서 읽는다. → 설치 파일에는 `--no-deps`로 넣는다(`build-python.mjs`의 `NO_DEPS`).
- **Windows에서 테스트가 그래프 파일을 지우지 못했다(`WinError 32`).** → `with sqlite3.connect(...)`는 트랜잭션만 끝내고
  연결을 닫지 않는다. → `contextlib.closing`으로 닫는다(`memory/graph.py`의 `_db`는 매 호출 연결을 닫는다).

## 2. 프로세스 수명주기 (Electron · 백엔드)

- **앱을 꺼도 python·claude 프로세스가 남는다.** → 부모가 죽어도 손자 프로세스는 남는다.
  → 백엔드가 Windows kill-on-close Job을 만들어 자식을 넣는다(`kill_children_with_me`). Electron의 자식은 libuv Job이 담당.
  작업 관리자 강제 종료에도 잔존 0 확인.
- **종료 신호로 stdin EOF를 쓰자 백엔드가 멈췄다(서브프로세스 생성 교착).** → Windows에서 stdin을 읽으며 블록된 스레드가
  있으면 이후 `subprocess` 생성이 교착된다. → 폐기. Electron이 `POST /shutdown`을 보내고 실행마다 새로 만든 토큰
  (`PHRO_SHUTDOWN_TOKEN`, 헤더 `X-Phro-Shutdown`, hmac 비교)으로 인증한다. 30초 안에 안 끝나면 강제 종료.
- **같은 DB에 서버 두 개가 붙어 그래프가 꼬일 수 있다.** → DB 옆 `.lock` 파일을 잠근다(`server.lock_database`).
  OS가 프로세스 종료 시 해제하므로 크래시 후 잔류 잠금이 없다.
- **투영(그래프 쓰기) 중 강제 종료.** → 재시작 시 pending 세대를 폐기하고 재구축. 활성 그래프 1개, 중복 간선 없음 확인.
- **클라이언트가 응답 도중 끊으면 서버 로그에 ConnectionError 트레이스백.** → `handle_one_request`에서 연결 오류를 삼킨다.

## 3. 기억 추출 · 검증

- **질문 턴에서 추출이 5회 재시도 끝에 dead가 되며 정상 주장까지 사라졌다.** → Claude가 비서 답변을 근거로 인용한 주장을
  섞으면 결과 전체를 버리고 재시도했다. → 근거가 사용자 발화가 아닌 주장만 버린다.
- **검증 응답의 맞는 판정이 버려졌다.** → 응답이 설명 뒤에 JSON을 붙이고 설명 속에 `[27]` 같은 괄호가 있으면, 첫 괄호부터
  끝 괄호까지 읽는 파서가 실패했다. → 마지막 JSON 객체를 읽는다(`server.as_json`, `graph.last_json_object`).
- **이직 기억("이제 카카오 다녀")이 검증에서 거절됐다.** → 추출이 이전 회사에 `NOT_WORKS_AT`을 지어냈다(사용자가 말하지 않은 부정).
  → 추출 지시 `RELATION_RULES`: 이사·이직·전학은 새 값만 내고, 사용자가 말로 부정하지 않은 옛 값에 NOT_을 붙이지 않는다.
- **추출 생략 규칙이 계획 사실을 놓쳤다.** → 처음엔 질문만 있는 턴을 모두 건너뛰었는데 "오사카 준비물 뭐 챙길까?"는 여행 계획을
  전제한다. → 생략은 회상·가정·양자택일 질문만. 연결어미·과거형이 섞이면 추출. 애매하면 항상 추출 쪽(`service.question_only`).
- **요약이 영어로 나왔다.** → 지시에 언어가 없었다. → 대화 언어로 쓰라고 지시.
- **같은 사람이 "민준"과 "사용자" 두 노드가 됐다.** → 추출이 주어를 섞었다. → 사용자는 항상 "사용자", 이름은 `사용자 HAS_NAME 민준`.
  검증 지시에도 같은 규칙을 넣어, 규칙대로 쓴 관계(도시 단위 장소 등)를 "세부 누락"으로 거절하지 않게 했다.
- **검증을 haiku로 바꾸자 오사카 계획·부산 이사가 거절됐다(3회 중 3회).** → 검증 지시에 날짜 규칙이 없어, 규칙대로 쓴
  `expires_at`(일정 다음 날)을 "지어낸 날짜"로 봤다. 추출은 "지난주"를 "9월 마지막 주 무렵"처럼 부정확하게 풀었다(기간 규칙 없음).
  → 검증 지시에도 `DATE_RULES`를 넣고, 기간은 범위("2026-09-28~2026-10-04")와 첫날 `valid_from`으로 쓰게 했다. sonnet은 같은 입력을
  받아들였다.

## 4. 그래프

- **"사용자는 서울에 살고 있다"의 관계가 그래프에서 사라졌다**(로그: `Target entity not found in nodes for edge relation: LIVES_IN`).
  → 로컬 qwen2.5:3b의 분리된 엔티티 단계가 끝점("서울", "커피")을 빠뜨려 관계가 통째로 버려졌다. 로컬 추출 성공률 1/6,
  프롬프트 변형도 2~25%로 불안정. `json_schema → json_object` 변경은 효과 없음(적용 안 함).
  → Claude 추출이 검증된 트리플을 내고 그래프에 그대로 넣는다(16/16, 지금은 `Graph.ingest`). 키워드 검색이나 구형 KG로 우회하지 않았다.
- **정정(서울→부산)이 옛 주소를 무효화하지 않았다.** → 관계명이 제각각(`MOVED_TO`, `DOES_NOT_LIVE_IN`)이었고, 로컬 모델이
  `NOT_LIVES_IN 서울`을 `LIVES_IN 서울`의 중복으로 합쳤다. → 어휘 고정(거주는 `LIVES_IN`, 부정은 `NOT_X`) + 규칙 판정(`Graph._resolve`).
- **규칙으로 못 정하는 충돌(이직 vs 취향 추가)을 판정할 주체가 없었다.** → 로컬 3B를 제거하면서 생긴 공백.
  → 사전 밖 관계만 Claude haiku가 판정(`Graph._judge`).
- **그래프 라이브러리의 엔티티 병합이 다른 사람을 "사용자"로 합쳤다("지연", "민호").** → 유사도+모델 병합. → 관계 끝점은 Claude가 검증한
  이름이므로 정확한 이름으로 식별하고 병합 단계를 거치지 않는다.
- **라이브러리의 `remove_episode`로 기억을 빼면 다른 기억이 근거인 엣지까지 지워지고, 무효화됐던 엣지가 살아나지 않았다.**
  → 자체 `Graph.remove`: 출처가 모두 빠진 엣지만 삭제, 공유 엣지는 남은 기억 문장으로 재작성, `invalidated_by`로 무효화 복원.
- **기억 1개 보관에 전체 재구축 153초.** → 보관·복구·소급마다 전체 재구축. → 증분 반영(바뀐 기억만 빼고 넣기), 0.1초.
- **옮긴 DB의 인출이 영구히 degraded.** → 그래프 이름이 DB 경로 해시라, 새 경로에서 옛 그래프를 검색하다 소유권 검사에 걸렸다.
  → `runtime.graph_owner`에 경로 기록, 다른 경로면 자기 그래프를 다시 만든다(이동이면 옛 그래프 삭제, 복사본이면 유지).
- **1천 개 기억에서 근거 포함률 72%.** → 한국어 조사가 키워드 색인을 깨고, 임베딩은 이름 구분이 약해 모든 LIKES 사실과 경쟁.
  → 질문에 나온 엔티티 이름의 엣지 안에서 먼저 검색(`Graph._anchors`), 100%.
- **업스트림 그래프 라이브러리가 익명 사용 통계를 PostHog로 보내도록 기본 설정돼 있었다.** → 라이브러리째 걷어냈다
  (SQLite 그래프로 교체, 1절). 옛 기록 라벨(`graphiti`, `memory_engine`, `graphiti-extracted`)은 `Store` 초기화가 새 라벨로 바꾼다.

- **대화형 질문의 기억 인출이 18문항 중 7개만 맞았다**(`tests/eval_memory.py`). 직접 질문·정정만 맞고 나머지가 빠졌다.
  → 원인별: 엣지 없는 기억(감정·사건, 관계 `[]`)은 인출 경로가 없었다. 인출이 현재 문장만 봐서 "그분", "그거"를 풀지 못했다.
  주어가 생략된 개인 질문("다가오는 여행 일정 있어?")은 앵커가 없어 남의 사실이 상위를 차지했다. "어머니"처럼 이름 대신
  관계로 부르면 연결되지 않았다. 기한이 지난 일정은 아예 버려져 "지난 여행"을 떠올리지 못했다.
  → 엣지 없는 기억의 문장 색인, 직전 사용자 메시지의 앵커, 기본 주어 "사용자", 앵커와 이어진 사람으로 한 단계 확장,
  날짜 추출과 "지난 일" 표시(`memory/graph.py`, `memory/service.py`). 18/18. 문항 수가 작아 새 실패 유형은 문항부터 추가한다.
- **respond가 thinking을 끈 줄 알았는데 켜져 있었다.** → `alwaysThinkingEnabled: false`는 효과가 없고 thinking은
  `--effort`가 정한다(CLI 기본 high, 답변당 thinking 약 130토큰). → `--effort medium`을 명시한다(`server.claude`).
- **`sonnet` 별칭이 최신이 아닌 `claude-sonnet-5`로 연결됐다**(CLI 2.1.282). → 모델 ID를 고정한다(`server.MODELS`, 5.5).
  이 CLI는 5.5 ID를 모르는 모델로 경고(stderr)하지만 응답은 정상이다. 비용 계산이 맞는지는 CLI 업데이트 후 확인한다.

- **"지난주에 부산으로 이사했어"가 옛 거주지(서울)를 무효화하지 못하고 오히려 무효가 됐다**(scenario_full).
  → 날짜 추출 후 "늦은 valid_at이 이긴다"가 성립일(사용자가 말한 지난주)과 기본값(서울을 말한 오늘 시각)을 비교했다.
  날짜를 말하지 않은 사실의 시작은 모르는 것이다. → `memories.valid_from_stated`로 둘을 구분하고, 둘 다 말한 날짜일 때만
  날짜로, 아니면 나중에 말한 쪽이 이긴다(`graph.later`). 응답 프롬프트도 "YYYY-MM-DD부터"(성립일)와 "기록 YYYY-MM-DD"를 나눈다.

## 5. 삭제 · 출처

- **보관한 기억이 이전 답변을 통해 다시 등장했다.** → KG 검색은 비었지만 대화 문맥에 "서울에 살고 계세요"가 남았다.
  → 서버가 직접 인출한 문맥의 원문 메시지 ID를 `response_drafts`에 두고 커밋 때 `turn_dependencies`로 기록, 보관 시 의존을 따라 전파.
- **사실 하나를 보관하자 이후 11턴과 주소 정정까지 함께 사라졌다.** → 후속 턴 전체와 그 기억까지 묶었다.
  → 근거 턴만 통째로, 그 사실을 문맥으로 본 이후 턴은 답변만 숨긴다(`turns`/`reply_turns`).
- **회상 답변이 맞아서 KG 검색 실패를 놓쳤다.** → 최근 대화만으로도 답할 수 있다. → 검사는 답변이 아니라 실제 관계·출처 인출로 판정.
- **"반영 완료"인데 검색이 안 됐다.** → 반영은 투영 상태일 뿐. → 기억별 `linked`/`no_relation`/`missing` coverage를 노출.

## 6. 데스크톱 앱

- **첫 실행에 캐릭터가 안 보였다.** → 시트 첫 로드가 실패하면 그리기 루프가 시작되지 않았다. → `requestAnimationFrame(draw)`를
  `load()`보다 먼저 시작(`overlay.js`). 나중에 도착한 시트도 그린다.
- **처리 기록의 "확장 후보" 탭이 통째로 죽었다.** → `trace.js`의 괄호 하나 초과(구문 오류) — 모듈 스크립트라 화면이 조용히 빈다.
  → `test-pages.mjs`가 모든 페이지 스크립트를 `node --check`로 파싱한다.
- **Windows 기본 창 끌기는 외곽선만 보이고 놓을 때까지 창이 멈춘다.** → 드래그를 JS+IPC로 처리.
- **시트 다운로드가 403.** → 사이트가 urllib 기본 User-Agent를 차단. → `phro-secretary/0.1 pet-catalog` User-Agent 지정.
- **`npm run dist`가 EBUSY로 실패.** → 실행 중인 phro-secretary.exe가 `build/dist/win-unpacked`를 잠근다. → 앱을 끄고 빌드.
- **설치 파일에 빌드 PC 사용자 경로가 들어갔다.** → pip가 만드는 `site-packages/bin/*.exe` 런처에 빌드 Python 경로가 박힌다.
  앱은 쓰지 않는다. → `build-python.mjs`가 설치 후 `bin`을 지운다.
- **코드 서명.** → 개인용 Azure Artifact Signing은 미국·캐나다만, OV 인증서는 유료. → 서명 없이 배포, SHA-256을 따로 전달.

## 7. 테스트 · 도구

- **purge 검사가 실패했는데 제품은 정상이었다.** → 검사가 근거 턴을 특정 턴으로 고정했는데, 실제로는 검증이 그 턴의 날짜 환산을
  거절해 다음 턴에서 확정됐다. → 보관 결과의 `message_ids` 기준으로 검사(`tests/scenario_full.py`).
- **E2E "second preview"가 가끔 실패.** → 복구 직후 기억 목록이 한 번 더 다시 그려져, 그 전에 누른 행의 클릭이 사라졌다.
